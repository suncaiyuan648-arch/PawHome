# PawHome 复用组件设计规范

> 文档建议落盘位置：`docs/pages-design/复用组件.md`  
> Figma 文件：`03pt0RiVfBFCvn4PsIyezk`  
> 设计基准宽度：375px  
> 技术栈：Vue 3 + uni-app + Vite + Less/SCSS  
> 参考代码：PawHome 当前源码  
> 参考页面规范：`docs/pages-design/首页.md`、`动态详情.md`  
> 文档目标：建立 **Figma → 代码组件 → 交互 → 动效 → 验收** 的统一真源，避免每个页面继续复制一套相似 UI。

# 1. 结论先行

这份 Figma 已经存在一定程度的组件复用，但 **Figma 自身的组件治理还不够成熟，不能直接把 Figma Component 一比一翻译为代码组件**。

本次全文件盘点得到：

```text
Figma 本地 COMPONENT / COMPONENT_SET：17 个
Figma INSTANCE：1127 个
全文件节点：22176 个
```

其中大量真正高频的 UI 仍然只是普通 Frame / Group，或者使用了无业务语义的名字：

```text
Group 1321318288
Frame 1321318310
Group 1321318301
Frame 1321318274
...
```

甚至存在：

```text
不同 component id 使用相同名字 Group 1321318288
```

因此代码侧应该建立一套**语义化组件系统**，而不是照搬 Figma 图层名称。

本次建议把 PawHome 的复用层分成 5 级：

```text
P0 Foundations
    Token / SafeArea / Motion / Icon

P1 Primitives
    Button / Badge / Avatar / Chevron / EmptyState

P2 Common Compound Components
    PageNav / Tabs / Search / Dialog / BottomSheet / Result

P3 Domain Shared Components
    YardSummary / FeedRank / Comment / DynamicMedia / FeedSource

P4 Page Composition
    首页 / 动态详情 / 小院详情 / 搜索 / 领养流程等
```

**页面只能组合组件，不应该继续复制组件样式。**

# 3. 不应该被业务代码重复绘制的系统层

Figma 中出现大量：

```text
Notch
Network Signal
WiFi Signal
Battery
Time
Home Indicator
微信小程序胶囊
```

这些只是设计画板为了还原设备视觉而绘制的元素。

## 代码规则

### 微信小程序

以下内容应优先交给平台：

```text
Status Bar
微信胶囊
Home Indicator / Safe Area
```

不能在业务页面重复画一份假的系统 UI。

### H5 设计预览

`PawPageNav` 和业务页面同样不得为了截图对齐重绘状态栏、微信胶囊或 Home Indicator。若设计评审确实需要完整设备壳，只能放在独立的 Dev Preview Shell，并且：

```text
不进入业务页面组件
不进入 MP-WEIXIN 产物
不参与业务布局高度计算
```

因此需要统一：

```text
PawPageNav
PawSafeArea
```

顶部导航的详细 API、原生胶囊透明占位、底部系统拖动条禁绘规则和静态门禁见：

```text
docs/AGENTS-native-ui-rules.md
docs/pages-design/PawPageNav.md
```

而不是每个页面分别写：

```css
top: 113px;
padding-bottom: 34px;
margin-top: 11px;
```

# 6. 基础视觉 Token

## 6.1 当前设计系统存在的问题

当前：

```scss
--paw-color-brand: #ffdd00;
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "PingFang SC",
  ...
```

而 Figma 全文件统计中高频品牌黄为：

```text
#FFE60F：212 次
```

首页和多个页面还出现：

```text
#FFE60D
#FFE600
#FFF463
#FBC800
```

因此需要定义**语义色**，不能让页面随意挑黄色。

# 7. 字体规范

Figma 全文件最常出现字号：


| Token | px | 典型用途 |


# 14. `PawAvatar` / `PawAvatarStack`

```vue
<PawAvatar
  :src="..."
  :size="34"
  @click="..."

```

```text

size
fallback
shape = circle

```

```text

```

```text

```

# 36. `PawOverlay`

所有：

```text
Dialog
BottomSheet
ActionSheet
ReplyComposer
Share
FeedPopup
```

都必须基于同一个 Overlay 生命周期。

## 为什么

目前大量组件：

```vue
<view v-if="visible">
```

直接挂载/卸载。

这意味着：

**关闭时根本没有 exit animation 的机会。**

---

## 推荐内部状态

```ts
rendered: boolean
opened: boolean
closing: boolean
```

Open：

```text
modelValue=true
→ rendered=true
→ nextTick
→ opened=true
```

Close：

```text
opened=false
→ 等 exitDuration
→ rendered=false
→ emit after-close
```

## 定位与内容职责

`PawOverlay` 只负责全屏遮罩、显示开关和生命周期，内容通过 slot 由页面或上层业务组件自定义。

```ts
props:
  modelValue?: boolean
  visible?: boolean
  placement?: 'top' | 'center' | 'bottom' // default: 'center'
  closeOnMask?: boolean
  zIndex?: number | string
```

`placement` 只决定 slot 内容在全屏容器中的上、中、下对齐，不负责内容自身的尺寸、内边距或业务布局。

Overlay 负责：

```text
z-index
scroll lock
mask
touchmove prevent
escape/back 行为
safe area
animation lifecycle
```

页面不再自己写一套 mask。

# 71. 图标治理

Figma design-to-code 已明确要求：

**图标 glyph 必须一致，不能因为名字差不多就拿 generic icon 替代。**

PawHome 当前常见问题：

```text
uni-icons hand-up
uni-icons chat
uni-icons redo
uni-icons eye
```

和 Figma 图标并不完全相同。

## 规则

优先级：

```text
1. 仓库已有与 Figma 一致的本地资源
2. Figma 原始 SVG 导出并落库
3. 项目已有 icon component 且 glyph 完全一致
4. 才考虑通用 icon 库
```

`PawIcon` 的 `size` 表示 canonical `24 × 24` design canvas 映射后的 CSS 边长，运行时布局框永远是 `${size}px × ${size}px` 方形。所有已注册 SVG source 必须在 source/build 阶段归一到 `viewBox="0 0 24 24"`；构建期按绘制内容的最长边统一适配到约 `22 × 22` design units，四周各保留约 `1` unit 安全余量；Figma 的旧 frame、透明留白和必要的光学修正必须用 24-unit design coordinate 的 source-level matrix 烘焙，`offsetX/offsetY` 不是 CSS px。运行时只做 `runtimeScale = size / 24` 的等比缩放，不得按 `16/20/24/28/32` 分支设置 padding、width、height、translate、stroke 或 image 尺寸。

微信小程序端 `PawIcon` 必须启用 `virtualHost`。否则组件宿主节点会以父级字体的 `line-height: normal` 参与布局；例如 `size=16` 时，宿主节点可能报告约 `16 × 19.29px`，即使内部根节点已经是 `16 × 16px`。图标 image 使用根节点的正常 flex 流，不使用绝对定位；根节点保留 `line-height: 0` 和 `overflow: hidden`，前者消除行盒影响，后者防止旋转 artwork 越出 layout box。`overflow: visible` 不属于 PawIcon 的尺寸修复方案。

`PawIcon` 支持正整数和小数 size（例如 `17.5`、`23`、`37.5`），不得 `Math.round`、`Math.floor` 或 `parseInt` 处理用户输入；建议范围为 `8～96px`，超出范围只在开发环境 warning。公共变换 API 只有 `rotate` 与 `flip`：旋转和翻转均以 PawIcon 方形布局框中心（`50% 50%` / SVG `12,12`）为原点，且不改变 layout box；测试必须覆盖 `0/45/90/135/180/270°` 与水平、垂直、双向 flip。

`icons:analyze` 默认逐个真实栅格化检查 `16/17.5/19/20/21/23/24/25.5/28/31/32/37.5px`，输出每个尺寸的 `paintedWidth/size`、`paintedHeight/size`、`paintedCenter/size`、最长边 live-area 比例、padding、stroke 和 transform 结果。最长边目标为 `22/24`，四周不能接触容器边缘；Normalized bounds 偏差超过 `2%` 为 WARNING、超过 `3%` 为 ERROR；normalized center 偏差超过 `1.5%` 为 WARNING、超过 `3%` 为 ERROR，并检测裁切、非线性缩放、padding 突变、stroke anomaly 与 `non-scaling-stroke`。需要临时验证其他业务尺寸时，可执行 `npm run icons:analyze -- --sizes 12,16,17.5,23,24,37.5,48`。

`pages/dev/paw-icon-lab` 提供 `Optical`、`Size Regression`、`Size Comparison`、`Transform` 四种模式；`Size Comparison` 必须把 `16/20/24/28/32/37.5px` 放在同一基线，不能只凭单张标准尺寸截图判断通过。完整验收至少保留 16px、24px、37.5px 全库截图、Size Comparison 截图、45°/90°/180°、水平/垂直 flip 截图，以及 `.artifacts/paw-icon-v2/optical-report.json` 和异常图标清单。

页面不得再通过 `width`、`height` 或固定 `flex-basis` 覆盖 `PawIcon` 的尺寸；如果需要固定点击热区，应在外层按钮/容器上设置尺寸，让图标本身保留 SVG 比例。

横向分隔线不属于 `PawIcon`：使用 `PawDivider`，不要把 `23 × 0.3` 这类非图标资源注册成方形 icon。

禁止使用 7 天失效的：

```text
https://www.figma.com/api/mcp/asset/...
```

直接提交生产代码。
