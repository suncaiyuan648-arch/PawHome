# 线下活动

## 页面与语义路由

- 列表页对应 Figma `83:23943`，详情页对应 `83:24014`，创建表单对应用户指定节点 `83:4577`。
- 业务归属为独立的 `packages/activity` 子包，页面目录采用 `pages/offline/list` 与 `pages/offline/detail`。
- 首页线下活动卡片使用语义路由 `activity.offline.list`，路径为 `/packages/activity/pages/offline/list/index`。
- 列表卡片和“报名”入口使用 `activity.offline.detail`，路径为 `/packages/activity/pages/offline/detail/index`，必须传入经过路由合同校验的 `activityId`。
- 页面状态（进行中、已结束）留在列表页内部，不通过状态参数复制出多条路由。活动详情按 id 读取；未知 id 显示无效入口状态，不回退到另一条活动数据。

## 列表页（83:23943）

- 375px 画板顶部插画区域从 `y=-38` 开始，宽375px、高268px。标题属于插画，不重复绘制。
- 白色活动筛选栏从 `y=198` 开始，高42px，顶部圆角10px。当前状态为“进行中”，右侧排序文字为“马上开始”。
- 页面底色为 `#F5F6F6`。列表卡片从 `y=247` 开始，左右各15px，卡片宽345px、高149px，圆角11px，纵向间距8px。
- 卡片使用横向 Flex：左侧封面固定112×149px，右侧信息区 `flex:1`，纵向 Flex 排列活动状态/标题、日期、地点、发起人，以及报名成员/操作按钮。窄屏时文字截断，封面保持比例，不横向滚动。
- 进行中与已结束是同一个列表页的本地状态；卡片与报名按钮都进入同一个活动详情路由。
- 列表页左上角使用与详情页首屏相同的 Figma 42×42px 圆形返回按钮，放入 `PawPageNav` 的 `#content` 插槽；点击返回上一级，直接进入列表时回到首页。
- “马上开始”排序指示箭头朝下。
- 列表页底部使用共享 `PawFixedActionBar` 固定“发起活动”按钮，使用活动详情报名按钮的黄色圆角主操作样式并预留安全区；滚动内容留出底栏空间。点击进入活动创建表单。

## 创建表单（83:4577）

- 画布层名称沿用“发布-创建小院”，可见内容是“Hello，欢迎发起线下活动”表单；以用户指定节点和可见内容为准。
- 黄色顶部标题区使用共享 `PawPageNav` 返回；系统状态栏与微信胶囊只由宿主绘制。其下依次是图片上传、活动标题、时间、地点、要求、联系方式、500字详情、至少3个活动标签和固定底部“提交”按钮。
- 图片上传、文本输入、地点选择和固定提交栏优先复用已有组件。时间使用小程序原生日期／时间选择器；校验标题、图片、起止时间、地点、联系方式、详情和标签。当前没有活动发布接口，提交校验通过后须明确说明尚未发布，不写入真实活动数据。

## 详情页（83:24014）

- 顶部活动图片画框为375×371px。活动摘要卡从 `y=354` 开始，高174px，覆盖图片下缘17px；其后“活动详情”卡从 `y=536` 开始，高102px，“活动发起人”卡从 `y=646` 开始，高117px，留言卡从 `y=771` 开始，高341px。
- 主要内容按纵向 Flex 排列；活动摘要的时间、地点和成员信息按横向 Flex 排列。卡片宽度随可用视口宽度变化，不用固定整页宽度。
- 底部复用 `PawFixedActionBar` 的线下活动样式：左侧分享按钮打开共享 `ShareActionSheet` 底部弹窗；弹窗携带当前活动的标题、封面和详情路由，点击“微信”再调用原生分享，朋友圈分享保留活动标题、封面与 `activityId`。右侧报名按钮保持 Figma 的黄色圆角样式。安全区仅用于留白，不绘制 Home Indicator 或系统拖动条。
- 已结束活动的详情页保留分享入口，底部主按钮显示“活动已结束”并禁用；活动状态标记使用已结束灰色样式。
- 留言区复用 `CommentComposer`、`CommentItem` 和 `ReplyComposerSheet`，标题数量与当前展示记录一致。演示数据允许在本次浏览中留言、回复和点赞，提交后明确提示仅本次浏览可见，不写入真实业务数据。
- `PawPageNav` 提供顶部导航几何与占位。详情页首屏使用透明导航叠在主图上，显示共享的 Figma 42×42px 圆形返回按钮；向下滚动后显示白色导航背景和 `PawPageNav` 通用左箭头（无圆形底），滚回顶部恢复首屏样式。详情页两种返回按钮都进入线下活动列表：上一级是列表时退回以保留列表状态，否则直接打开列表。滚动超过48px显示白色导航，回到24px以内恢复透明导航；中间区间保持原状态。滚动事件停止后读取 `scroll-view` 的实际 `scrollTop` 校准状态，覆盖快速惯性滚动时末次事件未报告停靠位置的情况；触顶事件仍立即恢复首屏样式。
- 活动数据当前为设计演示记录；报名按钮不创建真实报名记录。

## 资源与主包体积

- 页面、卡片组件、模拟数据和页面专属静态图均归入 `packages/activity` 子包，首页只增加语义路由入口。活动页面不把海报或照片塞进主包。
- Figma 列表插画与活动照片按原比例优化为 WebP：列表插画1206×804px、116,426 bytes；详情照片1000×811px、45,372 bytes。展示使用 `aspectFill`，保持比例裁切。
- 头像保留其 Figma 原始小尺寸；线性图标保留 Figma SVG 原始宽高，避免引入图标字体或图片处理依赖。
- 仓库主包目标为1.5 MiB；本次以子包隔离页面脚本与视觉资源，避免增加主包大图。构建报告仍需以最终微信开发者工具产物测量主包和 `packages/activity` 子包体积。
