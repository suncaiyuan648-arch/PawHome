# 动态详情设计校验与对齐记录

## 1. 校验基准

- Figma 文件：`03pt0RiVfBFCvn4PsIyezk`
- 设计基准宽度：375px
- 主画板：`62:27383`（动态详情，375 × 1629）
- 状态画板：
  - `62:27724`：动态详情-评论空状态（375 × 1565）
- 源码入口：`pages/dynamicDetail/index.vue`
- 路由：
  - 默认评论态：`/pages/dynamicDetail/index?yardId=1`
  - 评论空状态：`/pages/dynamicDetail/index?yardId=1&state=comments-empty`
- 关联组件：
  - `components/PawPageNav.vue`
  - `components/PawPrimaryButton.vue`
  - `components/PawStatusPill.vue`
- 可复用的已对齐实现：
  - 首页小院卡片：`pages/index/index.vue` 的 `.home-yard-*`
  - 排名用户滚动行：`components/SeamlessScroll.vue`
  - 排行摘要结构：`components/yard/YardFeedRankStrip.vue`
- 参考规范：`docs/pages-design/首页.md`
- 字体映射应与首页保持一致：Figma 的 Source Han Sans CN 映射为 `"Source Han Sans CN", "PingFang SC", sans-serif`。

### 当前结论

**FAIL — 当前动态详情尚未通过 Figma 视觉验收。**

页面已经具备动态详情的主要业务结构和两个状态，但核心视觉组件与 Figma 仍存在系统性差异，不能认定为“已对齐”。

目前比较接近或已经正确的部分主要包括：

- 路由与默认/评论空状态切换已经存在；
- 作者头像设计尺寸为 34px，源码也是 34px；
- 主媒体高度为 500px；
- 页面正文内容区通过 15px 左右内边距形成约 345px 内容宽度；
- 评论空状态插画最终覆盖尺寸已经调整到 78 × 79px；
- 评论空状态下底栏文案切换为「投点猫粮 / 入驻 / 领养」，默认状态切换为「云养一只 / 去看看 / 领养」，业务状态逻辑与 Figma 两个画板一致。

但以下区域仍不合格：

1. 主图使用 `scaleToFill`，与 Figma 的裁切逻辑不同，会产生图像拉伸；
2. 缺少主图底部的多图分页进度条；
3. 投喂来源头像堆叠尺寸、重叠量和标签尺寸均不一致；
4. 评论输入框结构与 Figma 完全不同；
5. 评论字体尺寸、点赞位置、语音评论、二级回复结构均未对齐；
6. 评论空状态错误地隐藏了评论输入框，并额外增加了设计稿没有的副标题；
7. 投喂排行榜的结构和尺寸与 Figma 明显不同；
8. 小院摘要卡与已经对齐的首页小院卡实现出现了重复造轮子，而且视觉退化明显；
9. 底部操作栏处于 `scroll-view` 内，不是固定底栏；
10. CTA 高度、颜色、图标均不符合设计；
11. 页面未统一使用首页已经确定的 Source Han Sans CN 字体栈；
12. 多处使用 `uni-icons` 近似替代 Figma 图标，而仓库内已经存在更接近设计的本地图标资源。

## 7. 动态主媒体

### 7.1 Figma

媒体外层：

```text
width: 375px
```

实际图像窗口：

```text
width: 304px
height: 500px
left: 35px
right: 36px
```

Figma 不是把整张图片强行压成 304 × 500，而是：

```text
容器 overflow: hidden
原图按比例放大
宽度约为容器的 236.9%
高度约为容器的 106.37%
top ≈ -3.18%
```

视觉结果是只看到横图左侧的猫，并保持猫本身比例正常。

底部还有两段分页进度条：

```text
height: 3px
gap: 3px
padding-left/right: 10px
active width: 176px
inactive width: 176px
border-radius: 2px
```

### 7.2 当前源码

```vue
<image
  class="hero-image"
  src="..."
  mode="scaleToFill"
/>
```

```css
.hero-image {
  width: calc(100% - 140rpx);
  height: 1000rpx;
  margin-left: 70rpx;
}
```

375px 基准下：

```text
width: 305px
height: 500px
left: 35px
right: 35px
```

几何只差约 1px，但最关键的问题是：

```text
mode="scaleToFill"
```

会把原始横图整体拉伸到窄高矩形中。

本地素材本身是横图：

```text
784 × 580
```

因此当前实现会产生明显的猫脸变形。

另外：

- 没有 Figma 的底部渐变；
- 没有两段分页进度条。

### 7.3 结论

❌ **关键视觉不合格。**

推荐使用：

```text
304 × 500 固定裁切窗口
overflow: hidden
image aspectFill
object-position / translate 复现 Figma 左侧裁切
```

如果追求像素级，可直接按 Figma 的 236.9% / 106.37% 比例实现。

**禁止继续使用 `scaleToFill`。**

## 20. H5 与微信小程序顶部适配风险

当前 `PawPageNav`：

H5：

```js
statusBarHeight = 44
navRowHeight = 58
```

动态详情额外：

```css
.hero-image {
  margin-top: 22rpx; /* 11px */
}
```

在 H5 中：

```text
44 + 58 + 11 = 113px
```

因此当前代码明显是在用 `11px margin-top` 间接把主图推到 Figma 的 y=113。

但 MP-WEIXIN 中 `PawPageNav` 使用真实胶囊：

```text
statusBarHeight
+
menu offset
+
capsule height
```

导航整体高度并不固定为 102px。

这意味着：

**同一套 `hero-image margin-top: 11px` 无法保证微信小程序端仍然从 y=113 开始。**

### 结论

⚠️ **H5 预览几何可能接近，但 MP 端存在顶部漂移风险。**

推荐让详情页面的：

```text
nav height
content start
notice y
author y
```

来自同一个 `navLayout` 计算结果，而不是各自：

```text
top: 113px
margin-top: 11px
statusBarHeight + 25px
```

分别补偿。

## 21. 当前源码中的样式治理问题

### 21.1 重复 selector

同一文件存在两组：

```css

```

前面：

```css

  height: 250px;
```

后面又覆盖：

```css

}
```

这说明当前动态详情是通过后置补丁逐步“压样式”，而不是保持一个明确的 Figma 真源。

### 21.2 px / rpx 混用没有明确层级

页面同时大量存在：

```text

15px
22rpx
16px
```

混用本身并非错误，但当前没有规则说明：

- 哪些是 Figma 固定像素尺寸；
- 哪些应该跟 375px 基准缩放；
- 哪些属于微信 safe-area。

这会让后续 AI 修改越来越容易产生 1～5px 漂移。

### 21.3 通用组件与 Figma 页面组件边界混乱

例如：

```text

```

属于通用组件。

但 Figma 动态详情中的：

```text

16px 高橙色小院标签
```

并不等于通用组件当前默认 variant。

不应为了动态详情直接修改通用组件默认值，否则可能影响其他页面。

正确方式：

```text
新增 variant
或
抽取 Figma 业务组件
```
