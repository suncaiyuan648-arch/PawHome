### 当前顶部内容布局约定（2026-08-29）

- `PawPageNav` 为 fixed 导航，并在文档流中提供等于运行时导航总高度的 placeholder；导航本身不包含页面间距。
- 动态滚动容器的 `top` 等于 `PawPageNav` 原生几何总高度，不再用固定 `113px` 或导航额外 padding 强行制造内容偏移。

### 18.2 当前源码的结构问题

模板：

```vue
<scroll-view class="dynamic-scroll">
  ...
  <view class="bottom-bar paw-safe-bottom">
    ...
  </view>
</scroll-view>
```

**Bottom Bar 位于 scroll-view 内部。**

CSS：

```css

  display: flex;
  ...
  min-height: 83px;

```

没有：

```css
position: fixed;
bottom: 0;
```

### 结论

❌ **这是 P0 级结构错误。**

当前底栏会跟随页面内容滚动，而不是像 Figma 一样固定在 viewport 底部。

```css

font-weight: 600;
```

Figma：

```text
height: 42px
background: #FFE60F
font-weight: Medium
```

当前还缺少 32 × 32 猫粮图标。

### 18.4 次级 icon

代码使用：

```vue
uni-icons redo
uni-icons eye / plus
uni-icons heart
```

```text

ruzhu.png      43 × 39  → 约 21.5 × 19.5
lingyang.png   42 × 42  → 21 × 21
```

这些尺寸与 Figma 明显更接近。

因此没有必要继续使用 generic `uni-icons` 近似替代。

### 18.5 安全区

当前虽然加了：

```html
paw-safe-bottom
```

但 `.bottom-bar` 自身又声明：

```css
padding: 12rpx 28rpx;
```

页面 scoped 样式可能覆盖全局 `.paw-safe-bottom` 的 `padding-bottom`，存在 safe-area 实际未生效的风险。

应避免依赖两个类互相覆盖 padding。

推荐拆成：

```text
.bottom-action-content
+
.safe-area
```

或者：

```css
padding-bottom: env(safe-area-inset-bottom);
```

明确计算最终 88px/设备安全区策略。

## 21. 当前源码中的样式治理问题

### 21.1 重复 selector

同一文件存在两组：

```css

}
```

这说明当前动态详情是通过后置补丁逐步“压样式”，而不是保持一个明确的 Figma 真源。

### 21.2 px / rpx 混用没有明确层级

页面同时大量存在：

```text

15px
22rpx
16px
```

混用本身并非错误，但当前没有规则说明：

- 哪些是 Figma 固定像素尺寸；
- 哪些应该跟 375px 基准缩放；
- 哪些属于微信 safe-area。

这会让后续 AI 修改越来越容易产生 1～5px 漂移。

### 21.3 通用组件与 Figma 页面组件边界混乱

例如：

```text

```

属于通用组件。

但 Figma 动态详情中的：

```text

16px 高橙色小院标签
```

并不等于通用组件当前默认 variant。

不应为了动态详情直接修改通用组件默认值，否则可能影响其他页面。

正确方式：

```text
新增 variant
或
抽取 Figma 业务组件
```
