# PawHome 页面路由与布局审计

审计日期：2026-09-08  
审计范围：当前工作区的 pages.json、全部 pages/**/*.vue 页面、页面与共享组件/工具中的 uni 路由调用，以及每个页面文件自身的 style/style lang=scss 块。  
落盘限制：本次只写入本报告，没有修改业务源码，也没有写入其他审计文件。

## 1. 结论摘要

- pages.json 注册 63 个页面；源码中发现 63 个 pages/**/*.vue；逐项对比结果为注册页面 63/63 有对应文件、页面文件 63/63 均有注册项，没有发现静态路由文件缺失或未注册。
- 主包 5 页，分包 58 页；自定义 tabBar 4 个入口，实际首个主包页面 pages/index/index 作为默认启动页。没有发现 entryPagePath 配置。
- 静态扫描到路由调用 149 处：pages 124 处、components 19 处、utils 6 处。调用类型为 navigateTo 102、redirectTo 16、navigateBack 21、reLaunch 8、switchTab 2。
- 将字符串拼接和 query 去掉后，没有发现确定指向 pages.json 之外的静态目标。需要保留一个未决项：shippingAddress 的 returnUrl 可以从 query 进入并交给返回辅助函数使用，当前调用者传入的是已注册页面，但运行时任意外部深链仍没有白名单校验。
- 静态反向调用检查发现 7 个没有源码直接调用者的注册页：adoption/pickCats、meMore/feedingDetail90、feedingDetail91、feedingDetail92、publishDynamic/postFeedOrder、dev/paw-icon-lab、dev/yard-feed-icon-lab。其中 3 个 feedingDetail90/91/92 是验收/别名页，不是同一页。
- feature/index 与 meMore/adoptionFlow 明显承载多种不相干或跨域模式，分别是高风险路由复用；extras、myAssets 也存在中等程度的多场景复用。yardCats、petDetail、feedingDetail、adoptionAudit、result 是同一业务域内的状态/流程复用，不直接判作“不相干业务”，但参数契约较重。
- 页面自身 CSS 中统计到 position:absolute/fixed 134 处，涉及 27 页；top/right/bottom/left/inset 890 处，涉及页面布局锚点的证据（含模板 inline style 的 4 处锚点）；transform 37 处。固定 width/height/font-size 等尺寸没有计入绝对定位。
- 原表的“高 18 页、中 5 页、低 40 页”是把 native chrome 风险、允许的 fixed 底栏/弹层/徽标覆盖和结构性绝对定位混在一起的启发式标记，不能直接作为结构性绝对布局结论。独立复核确认：首页、排行榜、功能页、用户资料、添加猫咪、yardCats 等页面有核心内容依赖绝对坐标的直接证据；PawPageNav、底栏、安全区、弹层、徽标等应单列为允许覆盖或 native-nav 风险。

## 2. 统计口径与证据规则

1. 路由真值以 pages.json 的 pages、subPackages.pages 和 tabBar.list 为准；文件路径统一补全为 /pages/...。分包页面实际路由为 root 与 path 拼接后的路径。
2. 页面参数同时从两侧读取：页面 onLoad/onShow/onReady 等生命周期中的 query/options 读取，以及所有页面、components/**/*.vue、utils/*.js 中显式 uni.navigateTo、redirectTo、reLaunch、switchTab、navigateBack 的调用者传入 query。没有把组件内部 props 当成页面 query。
3. 对字符串拼接路由，按静态基路径检查；已知的模板字符串或 query 拼接只要基路径在 pages.json 中，就不判作未知路由。无法从源码静态解析的 returnUrl、动态 path 记录为未决项。
4. “无调用者”指没有源码中的静态导航调用者，不代表开发者工具直接打开、外部分享、系统恢复或运行时动态链接一定不可达。
5. CSS 统计只看每个页面文件自己的 style 块，不把被引入的共享组件 CSS 合并进页面计数。P 是 position:absolute/fixed 声明数；A 是 top/right/bottom/left/inset 声明数；T 是 transform 声明数。行号为声明所在行。position:relative、固定尺寸和普通 flex/grid 不计入 P。
6. 结论分类：低表示绝对定位主要是徽标、状态点、缩略图按钮、局部装饰或未使用；中表示存在一个或多个页面结构层/抽屉/固定底栏的绝对定位；高表示核心页面骨架、顶部导航几何、原生胶囊模拟、时间线/榜单/地图等依赖绝对定位，或存在明显 native chrome 风险。

## 4. 页面布局与绝对定位审计

### 4.1 统计结果

扫描了 pages/**/*.vue 的全部 63 个页面 style 块。结果：P=134（27 页），A=890（含模板 inline style 的 4 处锚点），T=37。A/T 数量是声明证据计数，不能直接等价于布局错误；例如一个 position:fixed 的底栏通常同时产生 bottom、left、right 多个 A 声明。固定尺寸没有计入 P，也没有因为 width/height 较大而提高依赖等级。

允许或通常合理的类别：

- 导航和 native geometry reserve：PawPageNav、顶部占位、原生胶囊透明避让；
- 固定底栏/底部安全区；
- 弹层、遮罩、bottom sheet、操作菜单；
- 缩略图删除按钮、状态点、头像徽标、角标覆盖；
- 轮播指示器和局部装饰。

需要提高依赖等级的类别：

- 页面核心标题、城市、服务入口、榜单行、时间线、地图/邀请卡的主体排版依赖绝对坐标；
- 用绝对定位拼装本可由 flex/grid/flow 表达的页面骨架；
- 业务代码直接调用 getMenuButtonBoundingClientRect，或模板/CSS 重画状态栏、原生胶囊、系统手势条；
- position 与 top/right/bottom/left 虽少，但出现在固定全屏背景、主内容容器或核心卡片。

## 6. 发现、风险和未决项

### 高优先级

1. 统一顶部导航几何。12 个页面存在手动计算或直接读取原生胶囊几何的证据；这与 AGENTS.md 要求的 PawPageNav/navLayout 单一来源不一致。需要后续业务整改，但本次审计不修改源码。
2. 清理 native chrome 重画风险。index、annualReport、browsingHistory、helpedAnimals、postFeed、search、yardCertify、followFans、profile 等页面的模板/CSS 中出现状态栏、胶囊或其视觉组成的可疑证据，应逐项确认条件编译分支和真实运行端。
3. 拆解 feature/index 与 adoptionFlow 的路由模式。它们把多个不相干业务放在同一路由，参数校验和返回路径难以静态保证，建议形成明确的 route mode/typed query 契约或拆页。
4. 复核核心绝对布局页。首页、排行榜、feature、用户 profile、addKitten、yardCats 等页面的核心内容依赖 P/A；优先将可表达为 flex/grid/flow 的骨架迁移，保留确有覆盖关系的弹层、徽标和固定栏。

### 中优先级

1. 处理 extras.vue:72 到 helpedAnimals 的 id 未消费问题：删除无效 query，或让目标页明确读取并验证 id。
2. 明确 feedingDetail90/91/92、postFeedOrder、pickCats 的产品定位。若是验收/兼容入口，应在文档或 dev-only 组织方式中标明；若是生产流程，应补齐真实调用者。
3. 统一同域多模式页的参数别名：id/recordId、source/sourceType、reviewerRole/role、yardOwnerId/ownerPawId、state/variant 同时出现，建议形成单一解析层。
4. returnUrl 应限制为允许的内部路由集合，并保留不可用时的已注册 fallback。

### 未决项

- 本次是静态审计，没有启动微信开发者工具，也没有把截图或运行时页面栈当作证据；因此无法证明外部分享、历史页面栈、条件编译后的 H5/MP-WEIXIN 差异。
- 共享组件自身的 CSS 绝对定位没有合并到页面 P/A/T 计数；这是按“逐个页面”统计的口径。若要做最终运行时几何回归，应另做共享组件 CSS 与页面组合后的渲染审计。
- pages.json 没有 entryPagePath；默认入口判断依赖 uni-app 对 pages 数组第一项的约定，当前第一项为 /pages/index/index。
