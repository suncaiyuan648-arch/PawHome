## 2. 统一服务边界

沿用现有返回形状 `{ success, source, data, error }`，其中 mock 模式仍明确标注 `source: 'mock'`。不为了整齐强制改完所有无关工具 API。

- `applicationId`、`rescueId`、`orderId`、`reviewItemId` 分别指自己的实体；`recordId` 只在旧记录兼容层映射。业务层不得用一个没有域信息的 id 自行猜表。
- 读取：精确 ID→记录；不存在返回 `NOT_FOUND`，缺参返回 `MISSING_ID`，权限不足返回 `FORBIDDEN`。错误态不回落首条/最后一条 demo。
- 修改：先读取、校验实际 actor 能力和合法状态转换，再写入；页面参数只表示意图。路由参数通过校验不代表已经获得权限。
- 申请 type 必须是 `adoption|rescue`；现有 `normalizeType` 把任意未知值当领养的行为不能带入新 adapter。冲突的 type/source/sourceType 必须先失败且零写入。
- 评审 metadata 至少包含 `reviewItemId`、`applicationType`、对应实体 ID、状态及来自数据层的能力；由 resolver 查到以后再进入对应业务详情。旧 juryDetail 路径不能按图片或默认类型猜域。
- 已有状态迁移表继续是唯一依据；不借迁移开放重新审批，也不把“院主确认”直接映射到“奖励可领取”。

## 3. 幂等与失败

申请创建的请求去重、证实按人去重、投票一次性、奖励领取及订单创建各有自己的业务键。不要用全局节流代替幂等。

奖励领取必须满足：申请确实处于可领取状态、有效地址存在、同一申请复用已有成功创建的订单，保存失败应返回失败。读取旧 `recordId` 订单后不能再按新 `applicationId` 建一次。若写订单后申请状态写入失败，重试应找回原订单并继续合法转换；测试必须覆盖这个中间态。

现有 `createRewardOrder` 会吞掉 storage 写失败；改造时不得仍然报告成功。真实支付服务未配置仍显示明确未接入；治理不调用真实支付或发起真实申请。

## 4. 选择器与登录续接

- 直接 `navigateTo` 选择器可以沿用 eventChannel；路由壳发生 redirect 时不能假设原 channel 自动穿透。
- 跨壳路径使用显式 bridge：调用方生成 requestId，保存用途/调用方/草稿上下文；返回必须匹配 requestId，用一次后删除；取消也销毁。并行请求不能共享一个全局“最后选择”槽。
- URL 只放 requestId 和最小筛选 ID，不放姓名、手机号、地址全文或表单草稿。
- 重启、超时、重复回传和不存在 requestId 返回取消/过期，不能把结果写入另一个草稿。
- 登录/实名续接允许的目标来自 navigation 白名单；不接受任意 returnUrl、scheme、路径穿越。完成认证只恢复页面，让用户主动继续提交。
- 当前 `PAWHOME_ADOPTION_PICK`、`PAWHOME_LAST_ADOPTION_ID` 是历史状态，不再作为新详情路由缺少 ID 时的替代身份。旧草稿兼容读取与新 requestId 机制分开实现。

已落地的轻量桥见 `navigation/selectorBridge.ts`（C0-A5）。业务接入统一 import `selectorBridge` 共享实例；每页单独调用 createSelectorBridge 会失去跨页回传能力。地区 parts 保留现仓 1–4 级中文名称，允许直辖市同名层级；不杜撰地区 ID，不携带详细地址。回调须同步完成：回填本地状态后，异步业务由调用页自行处理；Promise 回调会报 ASYNC_CALLBACK_UNSUPPORTED 且请求已消费，不能重放。

### MP-WEIXIN 参数入口

2026-09-15 实测当前 SDK 3.15.2 / 仓库 uni 编译器：native page.options 和 Vue onLoad 写入值均保留百分号编码。URL 的 `state=%E7%8C%AB%20%252F%20%2B` 原样进入 Vue 状态，必须在小程序页面入口解码恰好一次，得到 `猫 %2F +`。

使用 `navigation/weixinLoadOptions.ts` 的 `decodeWeixinLoadOptions(options)`，只在 `#ifdef MP-WEIXIN` 分支调用；H5 已解码对象不可再调用。微信开发者工具/原生运行时可能把普通 options 对象放在另一个 JS realm，`isPlainRecord` 必须接受跨 realm 的标准 `Object` 原型，同时继续拒绝 class 实例。解码后再交 buildRoute 或 legacy resolver 做业务参数校验；坏编码不吞掉，参数不代表权限。原始 URL 字符串的 parseRoute/legacy resolver 已自带解码，不能先解码整条 URL。原生对象已丢失的重复 query 键无法由此适配器恢复，不能宣称它能验证原始 URL 的全部结构。

## 5. Coder 注册与集成顺序

每个域交付新增 pages 注册片段（root、pages、style）、语义名称与参数、旧壳适配表、调用方替换位置；总工按批串行合并 `pages.tson`。目标文件、注册、调用方和兼容壳共同构成发布单元。未注册目标不得被导航 helper 调用。

域 coder 的临时构建配置只能存在其独立工作树；handoff 必须指出临时变更并移除。公共路由注册不做整文件排序。根组件下沉前先检查所有引用者；多域真正共享的表现组件可以留公共层，但不得因此带入两域完整 fixture。

## 6. 必须交付的反例证据

1. 同时准备领养与救助记录，走救助创建/证实/审核后，领养集合及状态完全不变；反向亦然。
2. 不存在 ID、跨用户/小院 ID、伪造 managed/role/outcome、冲突的 type/source，均不展示替代记录、不触发写入。
3. 同一奖励请求调用两次仅一订单；storage 写入异常不能返回成功；恢复后重试仍关联同一申请。
4. 旧 key 的记录能被新页面查到、修改、返回刷新；不得启动时批量清旧数据。
5. 选择器确认、取消、双请求、返回壳、超时分别回到正确草稿；实名完成不自动创建申请。
6. 编译后跨域 helper 不携带域内 fixture/static；精确包字节和依赖链由 C0-B 报告确认。

上述测试须随对应服务/域实现落地，当前仅合同冻结，不提前记录 PASS。

## 7. 本轮采纳建议后的合同增补

以下约束立即适用于后续实现；具体枚举、接口和存储迁移由 11 对应 G-ID 交付，未实现不记 PASS。

- actor 来自会话/当前 mock 身份提供器；业务参数仅定位对象。能力至少按 actor 与对象归属、角色关系、状态及业务策略联合计算。读私密信息也须检查；写入前重新读取记录与能力，防止页面缓存过期。
- task 摘要包含 taskId、businessType、businessId、actorRole、actionType、status 和可选 reviewItemId。taskId 按对象+阶段+处理 actor 去重；摘要与审批记录分开，task 的 role/status 不授予写权限。已处理任务保留可读业务落点。
- 领养沿用 cloud_pending/pending 等已有状态与 cloudParentRequired；资金状态不合并进审核状态。补材料与重新审批是不同决策，未批准前保持重审关闭。
- 订单视图隐藏以 userId+orderId 为键，主体与合法履约访问不受影响。NORMAL_FEED/ADOPTION_GIFT 是建议语义，实施时适配现字段而非全局强制重命名；类型能力必须由可信记录派生。
- 反馈读模型至少表达策略版本、required/completed 次数、next/lastFeedbackAt 与超时信息；业务键区分同次重试和不同合法反馈。先确定删除/撤回证据与计数规则，再开放删除操作。
- 消息与任务深链使用业务 ID 和已注册白名单路由。旧状态仅作历史信息；进入详情重读当前状态/能力。认证续接不重放提交。

对应反例：A01 跨账号零写入，A02 条件审核，A03 多角色任务去重，A05 审核/资金分轴，A06 单用户隐藏与赠礼幂等，A07/A09 证据删除计数，A10 过期消息/认证恢复。
