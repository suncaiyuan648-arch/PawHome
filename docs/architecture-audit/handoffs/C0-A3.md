## 目标路由合同

`ROUTE_REGISTRY` 覆盖 06 矩阵中已确定的语义目标路径。实体 ID 统一为非空 ASCII 受限字符串：首字符为字母或数字，后续只允许字母、数字、`.`、`_`、`:`、`-`，最长 128。面向文本的 query（例如搜索词）允许 Unicode，编码只做一次；解析拒绝坏百分号、重复键、未知键、数组/对象值和 `__proto__`/`constructor`/`prototype`。

`adoption.apply` 要求 `yardId`，多动物上下文用逗号分隔的 `animalIds` 标量，最多 6 个且不可重复；数组形式明确拒绝。详情、进度、结果、确认、评审和证明等目标路由均声明 required ID。`adoption.animal-picker` 仅保留为 `fallbackOnly` 合同，不进入任何默认 active registry。

四个 Tab 仍使用原路径：`/pages/index/index`、`/pages/selfRun/index`、`/pages/message/index`、`/pages/me/index`。`navigateRoute` 必须注入实际已注册的物理 path 集合或 routeName→物理 path 映射；只有 route name 没有物理 path 时拒绝。无 active registry 直接 `NO_ACTIVE_REGISTRY`；Tab 始终调用 `switchTab`，不会拼 query。

selector 合同只约束 `requestId` 的输入/输出，并标记 `bridge: eventChannel`、`autoRedirect: false`。合同没有声称自动 redirect 或自动保留 eventChannel。

认证续接只开放 `adoption.apply`、`rescue.apply`、`yard.create`、`adoption.reward.claim` 四个显式 route name。`buildAuthContinuation`/`parseAuthContinuation` 会再次经过目标 route schema，并拒绝任意 URL、scheme、动态详情等未列入白名单的入口；helper 只返回合同，不执行导航或提交。

## 已覆盖的旧入口

| 旧入口 | 目标 | 关键规则 |
|---|---|---|
| `/pages/feature/index` | rescue detail / account invite / animal album | `mode` 必须明确；ID 缺失或未知 mode 失败；不回退首条救助；`managed` 等能力 query 不提权 |
| `/pages/meMore/adoptionFlow` | adoption/rescue progress | `type/source/sourceType` 冲突拒绝；`state=long` 明确 rescue，与显式 adoption 冲突拒绝；48→`adoption-info`、49→`application` 只读；其他 frame 不写入目标 query |
| `/pages/adoption/adoptApply` | adoption/rescue apply | `state=long`/rescue source 固定救助；显式 adoption 冲突阻断；领养需要 `yardId`，可带最多 6 个 `animalIds` |
| `/pages/adoption/adoptApplySuccess` | adoption/rescue result | 只接受 `application-submitted`；实体 ID 和业务域冲突拒绝 |
| `/pages/yard/juryDetail` | adoption jury detail / rescue review detail | `reviewItemId` 必填；按注入的真实 metadata `businessType` 分流；query 域与 metadata 不一致拒绝；缺 resolver 或无记录失败 |
| `/pages/publishDynamic/postSuccess` | dynamic result / feeding result | 兼容旧页真实 `state=feeding`；`state/type/mode=feeding` 只表达 `feeding-completed` 结果意图，`scene=feeding-feedback` 表达 `feedback-published`；两类意图冲突拒绝；feeding 必须有 `orderId`，dynamic 必须有 `dynamicId`；最终状态必须从订单/反馈记录验证，query 不能证明完成 |
| `/pages/meMore/myAssets` | yard animals / animal mine / account medals/map/achievement | 默认 pets 需要显式 `yardId`；`state=owned` 才进入我的动物；`mode=medals&first=1/true` 进入 achievement；`yardName` 等显示提示会丢弃；`role/managed/reviewerId` 不改变目标 |

旧入口中未列出的页面统一返回 `UNSUPPORTED_LEGACY_ROUTE`，不能把 63 行矩阵误报为已迁移。具体未覆盖的同域旧页、其内部 caller、页面注册和分包接入由 C0/C1–C8 后续任务负责。

## 未决与边界

总工集成补充（2026-09-13）：metadata 必须带匹配请求的 `reviewItemId` 或旧 `id`；两者同时存在须一致。多种业务类型字段同时存在也须一致，禁止 resolver 回落首条任务后仍继续导航。新增独立反例，集成后的本批测试为 15 组。

- 目标路径尚未写入 `pages.tson`，因此本批 `navigateRoute` 不提供默认 active registry，避免误调用不存在的 `packages/**` 页面。
- `adoption.apply` 的旧页面 caller 尚未补齐 `yardId` 与多选动物上下文；旧入口缺这些参数时合同会明确失败，不能偷偷找首只 demo 或从权限 query 推断。
- `reviewMetadataResolver` 的真实任务读模型由 jury/救助/领养域交付；本批只规定同步 metadata 形状和分流，兼容旧 `reviewType`/`juryType` query 并检查与真实 metadata 冲突，不提供 mock fallback。
- 其他 63 矩阵行、页面注册、业务数据双读/单写和 eventChannel 实际桥接未在本批宣称完成。
