# C2-P1 领养申请者进度页交接

## 交付范围

本批在 `packages/adoption` 建立申请者进度页组合：

- `packages/adoption/pages/progress/index.vue`
  - 新路由页面契约为 `/packages/adoption/pages/progress/index`。
  - 只接受必填 `applicationId`，并通过 `decodeWeixinLoadOptions`（MP-WEIXIN 边界）和 `buildRoute('adoption.progress', ...)` 校验查询参数。
  - `view` 只允许 `adoption-info`、`application`；这两个视图没有底部操作。
  - `onShow` 按同一 `applicationId` 重新读取，缺 ID、非法查询、无记录分别进入明确空态；不会读取最后一次领养单或演示记录。
  - 操作阶段只由已保存记录的 `status` 派生。申请者确认继续使用已注册的 `/pages/meMore/adoptionConfirm?recordId=...`；奖励地址继续使用已注册的 `/pages/adoption/submitOrder?recordId=...`，两者都保留同一申请单 ID。
- `packages/adoption/services/progress.js`
  - 领养域轻量 adapter，直接调用 `adoptionStorage`，读取时固定 `includeDemo: false`。
  - `beginReward` 只允许持久化 `adoption_confirmed` 单据进入 `reward`，演示单和无效 ID 均失败。
- `packages/adoption/components/AdoptionProgressView.vue`
  - 领养申请、宠物、领养信息、确认材料和拒绝说明的只读组合，不导入旧统一进度组件或救助 fixture。
- `packages/adoption/components/AdoptionProgressTimeline.vue`
  - 进度轨道由持久化状态的阶段映射驱动，使用 `PawIcon`，未重绘原生系统栏/胶囊/Home Indicator。

## 设计依据与边界

已按 `docs/design/figma-map.yaml` 和领养任务清单核对原申请者链路。Figma 精确节点 `62:31384`（等待审核）和 `62:33198`（获得奖励）已读取结构；奖励进度内容框为约 345×693，进度卡为 345×72。新页沿用这些内容层级与 `PawPageNav`/安全区规则，未把画板编号作为业务状态来源。没有 DevTools runtime 证据，因此本交接不声称运行时 Figma 对齐或真实接口接通。
