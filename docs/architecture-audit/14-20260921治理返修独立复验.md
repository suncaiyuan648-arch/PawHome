## 二、原始未通过项（本轮编号 F01–F06，已由返修复验更新）

### F01 / P1：领养写入仍接受冲突归属，奖励还放行无归属记录

位置：`utils/applicationMockApi.js:87–104`，调用点 `createRewardOrder`、`submitAdoptionEvidence`；实际确认材料与奖励弹层仍消费这些方法。

- authorizeApplicant 收集 applicantId/applicantUserId/userId/嵌套 applicant 多个身份后只做 includes(actor.id)，没有拒绝彼此冲突。
- 复现：当前 user-a，记录 applicantId=user-b、userId=user-a。submitAdoptionEvidence 成功，状态变为 owner_confirm_pending、写入 1 次；同样冲突的 reward 记录创建奖励订单成功、写入 1 次。
- allowLegacyUnowned 被注释成测试兼容，但真实 createRewardOrder 也启用它。带显式可信 actorProvider 的 user-a 对无申请人归属 reward 记录仍创建订单成功。该分支没有限制在测试依赖中。

退出条件：同一申请人身份的别名必须一致且有效；缺归属或冲突零写入；测试兼容在 fixture 层处理，不在生产调用服务放宽。补确认、奖励、读取、正常创建整链路反例。

### F02 / P1：反馈资格采用排除少数状态，取消/退款/未知订单仍写成功

位置：`packages/dynamic/services/feedbackPublisher.js:275–284`。

ensureEligible 仅拒绝 shipping/pending 等少数值。使用合法持久订单、动物、小院及当前院主，分别把订单 status 设为 cancelled、refunded、unknown，publishLocalFeedback 均成功，动态和证据各写一次（writes=2）。delivered 对照组同样成功。

这不要求接真实退款服务；本地已有或异常订单状态必须明确判断可反馈资格。反馈状态 feedbackStatus 还优先于订单状态，不能用它覆盖订单的终止资格。

退出条件：按批准合同列出可反馈的订单类型、履约状态及策略；未知、终止、不满足条件全部拒绝；每个合法状态配正向测试，各非法状态断言动态/证据零写入。

### F03 / P1：canonical animalId 在订单选择链中丢失，页面无法提交合法反馈

位置：`packages/dynamic/services/orderPicker.js` 的 getFeedingOrders 映射；`packages/dynamic/pages/editor/index.vue:288–325`。

- writer 与新测试使用 animalId/animalIds；picker 仅将 petIds/petId 转成 petIds，漏掉 canonical 字段。
- 复现：合法 order-a（animalId=animal-a）经 picker、页面 normalizeOrderForPublish 后 petIds=[]。applyOrderSelection 得到空 selectedPetIds/pickedCats，onPublish 的动物检查无法通过；手动选择动物又因相同缺失的 orderPetIds 把订单列表清空。
- 服务直调成功不能证明页面能构造相同有效输入。

退出条件：订单、选择器、页面、writer 共用一致的动物关联规范；从订单详情打开反馈，使用 animalId / animalIds 记录走完选择→正文媒体→发布→本次动态→证据计数；兼容别名有冲突时拒绝。

### F04 / P2：保存返回时没有重新读取公开详情和管理名册

位置：`packages/animal/pages/detail/index.vue:227`、`packages/yard/pages/detail/index.vue:56`、`packages/account/pages/profile/index.vue:506`、`packages/yard/pages/manage/animals/index.vue:65`、`components/PawPetRoster.vue:242–255`。

详情新增的持久读取只在 onLoad；管理名册子组件只在 created 和 variant/userPawId/yardId 改变时重读。编辑页保存没有给已有父页发送更新事件，也没有 onShow 刷新。正常详情/名册→编辑/新增→返回时页面实例与参数未变，仍保留旧名字/状态/列表，新增动物不立即出现。重新编译或重新打开页面的读回并不等于返回刷新完成。

退出条件：保存后返回既有页面可重读；名册、详情、身份切换权限重新判断；取消编辑不改原值。补页面生命周期层的验收，不只调 reader。

### F05 / P2：资料/小院编辑仍只有夹具入口，没有正常产品入口

全仓生产 Vue/JS caller 检索 account.profile.edit、yard.editor 和两个完整 editor 路径：除 routeContracts 定义、编辑页自身和 pages/dev/governance-fixture 外，没有正常业务跳转调用者。

因此“夹具能打开并保存”可以保留为子批次成果，但不能把当前用户资料和院主管理的实际编辑入口标为完整交付。

退出条件：从“我的/本人资料”和“本人小院管理”提供真实身份约束入口；非本人不可进入；保存与返回接 F04。若明确不做入口，需登记范围决策，不计全链路 DONE。

### F06 / P2：动物编辑未保存物种，新增狗在名册中变成猫

位置：`packages/animal/pages/editor/index.vue:318` 和 `:484` 保存 patch；`packages/animal/services/localManagementStorage.js` EDITABLE_FIELDS/createLocalAnimal；`utils/petRosterMockApi.js:62`。

页面通过 species=dog 设置 petKind，但保存 patch 不含 species，writer 白名单也没有 species/kind。按页面同形 patch 创建“金毛”记录成功，storedSpecies=null；再次读名册得到 rosterSpecies=cat。编辑既有狗时也没有从 record.species 初始化 petKind。

退出条件：明确持久化物种字段与合法值；创建/编辑/名册/品种选择一致；猫、狗分别验证保存、重进及分类计数。
