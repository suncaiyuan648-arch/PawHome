# PawHome 页面与组件架构审计任务清单

## 审计目标

梳理当前项目的页面文件、真实路由与参数、绝对定位依赖、组件引用关系，以及 Git 历史和目录/路由职责问题。每一项先由独立分析 Agent 落盘，再由全新的 reviewAgent 基于当前工作区和 Git 证据复核，最后由主线交叉检查并形成综合结论。

## 范围与口径

- 仓库：`/Users/a1-6/Documents/ChatGPT/逢猫`
- 路由真值：`pages.json` 的主包页面与分包页面；代码中的导航调用用于补充参数和调用关系。
- 页面文件：当前源码中的 `pages/**/*.vue` 页面入口/路由文件；非路由组件单独列入组件审计。
- 组件文件：源码根目录 `components/` 下的组件；与页面运行相关的自定义 TabBar 等目录另行说明；不把 `unpackage/` 构建产物当作源码组件。
- “未修改”：优先标记“文件引入后没有后续修改”（Git 路径历史只有引入提交），同时给出首次/最近提交，避免把“未修改”误解为从未进入 Git。
- 绝对定位：区分结构性布局 `absolute` 与导航、底部栏、弹层、徽标等合理覆盖层；不能只按 CSS 声明数量下结论。

## 约束

- 本轮是结构审计，不修改业务源码，不把分析推断写成已验证事实。
- 每条重要结论必须带文件路径、行号或 Git 命令证据。
- 分析 Agent 只能写自己的落盘文件；reviewAgent 只能写对应 review 文件，避免互相覆盖。
- 未完成的审计项不得标记为完成；发现证据不足时保留为“待确认”。
