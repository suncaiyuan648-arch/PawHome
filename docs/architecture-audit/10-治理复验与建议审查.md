## 阻断终验的问题

### P1：新 Figma 文件不能直接沿用旧节点

新文件 `ikwcujfbxtNcjk9tjGjKx8` 的 `0:1` 画布元数据使用 `83:*`，未出现旧 `62:*` 节点；精确查询旧首页 `62:23815` 返回 node not found。故只全局换 file key 会生成失效链接。

已更新索引当前文件地址；所有既有 node_id 显式保留旧 file_key，并标记 `pending-node-remap`。页面文档中的旧链接作为历史来源保留。下一批须根据页面职责、状态、文案和层级逐项核验映射，不能按相似截图、相同名称或编号偏移批量推断。矩阵 PASS 仅表示本地结构检查通过。

### P1：状态驱动已落地，actor 权限合同尚未完整接入

`packages/adoption/services/progress.js` 的 `readAdoptionProgress` 注释称 applicant-owned，但实际仅按 ID 查询；`statusPresentation` 仅凭 status 给出 canConfirm/canClaimReward，`beginReward` 也没有检查申请人身份。底层 `utils/adoptionStorage.js:getAdoptionById` 是按 ID 查找，`transitionAdoption` 只查合法状态边。这在单用户本地 mock 中不等同于线上漏洞，但不能验收为跨账号隔离或 capability 权限完成。

旧管理入口同样仍依赖表现参数：`pages/yard/yardCats.vue` 从 query.state 推导 managed，再传入宠物详情；`pages/adoption/components/PawPetDetailFigma.vue` 将 managed 或 variant=36 视为管理态。属于尚未治理完的权限债务，不应归因于组件下沉本身。

验收要求：以可信 actor 与对象归属计算能力，在写入 adapter 再次校验；用户 A 传用户 B 的 applicationId、伪造 managed/state/role，均不能获得写能力且零写入。补多角色反例后才可宣称权限治理通过。

### P2：构建通过与运行终验之间仍有缺口

既有 80 项测试不能替代真实旧入口→新页面→返回刷新、选择器确认/取消、双请求及跨角色处理链路。需完成 06 矩阵相应批次的交互、几何、视觉证据；尤其新文件地址改变后不能沿用旧视觉结论。主包余量约 4.85KiB，后续合入继续执行 final 门禁。
